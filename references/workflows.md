# 消保检查四角色工作流程与输出模板

## 角色路由

| 意图特征 | 激活角色 | 判断关键词 |
|----------|----------|------------|
| 制度/标准/计划 | 制度与标准建设者 | 制度、办法、标准、计划、评价标准、检查清单、管理办法、流程规范 |
| 检查/核对/审查/现场 | 检查执行者 | 检查、核对、审查、现场、抽样、访谈、查验、六大领域名称 |
| 整改/跟踪/督办/报告 | 整改督办者 | 整改、跟踪、督办、整改通知、检查报告、验收、复核、归档 |
| 统计/分析/总结/覆盖率 | 统计分析与报告者 | 统计、分析、总结、报告、覆盖率、完成率、趋势、季度、年度 |

**复合意图**：按业务逻辑顺序串行激活。典型编排：
- 检查-整改链：检查执行者 → 整改督办者
- 检查-整改-统计链：检查执行者 → 整改督办者 → 统计分析与报告者
- 统计-制度链：统计分析与报告者 → 制度与标准建设者
- 无法判断时，向用户提出2-3个选项澄清后再激活。

## 角色一：制度与标准建设者

**职责**：制定/修订《消费者权益保护检查管理办法》、建立/更新检查标准、制定年度检查计划、规范检查流程。

**刚性要求**：
1. 检查标准必须可执行：每个检查项明确"检查要点 + 检查方法 + 判定标准"三要素。
2. 检查计划必须量化：明确检查频次（如每季度综合检查、每月专项检查）、检查对象、时间节点。
3. 检查流程必须闭环：检查方案制定 → 检查通知发布 → 现场/非现场检查 → 问题记录 → 检查报告撰写 → 整改跟踪 → 档案归档，每环节有明确输入、输出、责任人。
4. 动态更新：每年至少一次审视检查制度和标准，与最新监管评价办法同步。

**工作流程**：
1. 识别需求类型（制度 / 标准 / 计划 / 流程规范）。
2. 检索依据材料：监管要求（金规〔2025〕20号，必要时查 21 版办法）+ 内部素材（存量制度、历年计划、报告模板、监管评价自评表）。检索顺序按 SKILL.md 第四步执行；用户未提供内部素材时，以 `references/` 为基线并在输出中说明。所有工作必须基于检索到的原文，杜绝幻觉。
3. 分支处理：
   - A 制定制度：依托监管要求 + 标准模板搭建框架（总则、组织架构、检查范围、检查方法、检查流程、检查纪律、结果运用、附则），填充内容输出初稿。
   - B 建立标准：将监管评价表每个评价要素拆解为内部检查项，为每项配置检查要点、检查方法、判定标准（达标/部分达标/不达标）、评分规则。
   - C 制定计划：根据机构规模、监管重点、历史问题规划全年安排（频次、对象、重点、时间表）。
4. 二次合规复核：反向检索知识库交叉核对，排查遗漏监管要求。

**输出格式**：
```markdown
## [任务标题]
### 背景与依据
- 任务类型：[制定制度/建立标准/制定计划]
- 监管依据：[引用的监管文件]
- 参考素材：[引用的内部文档]
### [主体内容]
[按制度文件的标准章节结构输出]
### 合规复核说明
- 已核对监管要求：[清单]
- 核对结果：[合规/存在待确认项]
### 附件
- [生成的文件列表及说明]
```

## 角色二：检查执行者

**职责**：按检查清单和标准对六大领域系统性检查，记录问题和证据。

**检查类型**：综合检查（全覆盖）/ 专项检查（特定领域）/ 跟踪复查。
**检查对象**：分支机构 / 业务部门 / 合作机构。

**工作流程**：
1. 接收检查任务，确定检查类型、对象、涉及领域。
2. 获取检查标准与被检查对象的历史检查记录、投诉数据（用户提供 → 资料库/知识库检索 → `references/checklists.md` 基线）。
3. 生成检查方案（检查项目、方法、标准、人员分工）和工具文档（检查记录表、访谈提纲、抽样方案）。
4. 逐项检查与问题记录（检查结果、问题描述、问题来源、影响权利、证据索引、严重程度）。
5. 输出检查发现。用户未提供证据材料时，输出"待核实项 + 数据/材料需求清单"，不得臆造检查结论。

**检查前准备要点**：制定检查方案 → 预研检查对象（调取制度文件、历史记录、投诉数据、监管评价结果）→ 发布检查通知。

**输出格式**：
```markdown
## [检查对象]消保检查记录
### 检查概况
- 检查类型：[综合/专项/跟踪复查]
- 检查领域：[涉及的领域]
- 检查对象：
- 检查日期：
### 检查发现
#### 领域一：[领域名称]
| 序号 | 检查项目 | 检查要点 | 检查结果 | 问题描述 | 严重程度 | 影响权利 | 证据索引 | 判定依据 |
|------|----------|----------|----------|----------|----------|----------|----------|----------|
| 1 | | | 达标/部分达标/不达标 | | 重大/中等/一般 | 如知情权 | 如"营销方案第3页" | 如"银保监会令2022年第9号第X条"（引行为规范类条款，不引评价办法） |
### 检查总结
- 检查项目总数 / 达标项数 / 部分达标项数 / 不达标项数 / 重大问题数
### 引用来源
[知识库文件名及具体条款]
```

## 角色三：整改督办者

**职责**：问题闭环管理——检查报告、整改通知、跟踪台账、效果验证、档案归档。

**工作流程**：
1. 整理检查发现为问题清单，按严重程度分级（重大/中等/一般），明确整改要求和时限。
2. 生成检查报告（检查概况、问题清单含依据、整改建议、时间要求）和整改通知（问题描述、整改要求、时限、责任人）。
3. 建立整改跟踪台账，状态流转：待整改 → 整改中 → 待复核 → 已闭环 / 超期。
4. 跟踪与督办：定期输出进度；超期问题发升级督办通知；整改完成后验证效果。
5. 档案归档：检查方案、检查记录、检查报告、整改通知、整改反馈全套材料。

**输出格式**：
```markdown
## [检查对象]消保检查报告 / 整改通知
### 检查概况
- 检查依据 / 检查范围 / 检查方式 / 检查时间 / 检查人员
### 问题清单与整改要求
| 序号 | 问题描述 | 严重程度 | 问题来源 | 影响权利 | 整改要求 | 整改时限 | 责任部门 |
|------|----------|----------|----------|----------|----------|----------|----------|
| 1 | | 重大/中等/一般 | 制度/流程/执行/结果 | 如知情权 | 改什么、怎么改、谁来改 | YYYY-MM-DD | |
### 整改跟踪台账
| 序号 | 问题描述 | 责任部门 | 整改措施 | 要求完成日期 | 当前状态 | 复核结果 |
|------|----------|----------|----------|--------------|----------|----------|
| 1 | | | | | 待整改/整改中/待复核/已闭环/超期 | |
### 引用来源
[知识库文件名或法规名称及具体条款]
```

## 角色四：统计分析与报告者

**职责**：检查数据统计分析、关键指标计算、季度/年度工作总结。

**工作流程**：
1. 数据收集：各次检查问题清单、整改台账、覆盖数据。
2. 数据分析：按问题类型（制度/流程/执行/结果）、严重程度、责任部门、检查领域分类统计；计算检查覆盖率、整改完成率；识别趋势（同比、环比）和异常。
3. 撰写报告。

**输出格式**：
```markdown

| 指标 | 数值 | 较上期 | 说明 |
```

## 异常处理规则

| 异常场景 | 处理策略 |
|----------|----------|
| 知识库检索无匹配 | 放宽条件重试一次；仍无结果用外部检索，输出标注 `[依据来源：外部检索，建议人工复核]`；不得编造标准 |
| 意图模糊无法判断角色 | 提出2-3个选项引导澄清 |
| 检查数据不足 | 列出缺失数据项，输出数据需求清单 |
| 上传文件无法解析 | 告知支持的文件格式，请求重新上传 |
| 任务超出能力边界 | 建议转交其他领域处理 |
| 检查标准与法规冲突 | 用外部检索验证最新版本，不确定标注 `[待验证]` |
| 链式执行某环节失败 | 已完成环节正常输出，失败环节跳过并说明 |

## 一致性要求

检查发现的"四要素"（问题描述 + 严重程度 + 判定依据 + 证据索引）、整改要求的可操作性（改什么、怎么改、谁来改、什么时候完成）、统计数据的同比环比对比，均以 SKILL.md"核心工作原则"与"输出要求"为准，本文件不重复定义。

补充两条易错点：

1. **判定依据要引行为规范、不引评价办法**：检查发现的问题依据应为《银行保险机构消费者权益保护管理办法》（银保监会令2022年第9号）、《金融机构产品适当性管理办法》（总局令2025年第7号）、《个人信息保护法》等行为规范类条款；金规〔2025〕20号用于说明评价要素归口与权重，不作为违规判定依据。
2. **整改时限要分级**：重大问题的整改时限一般不长于一般问题，且应明确"整改—复核—闭环"三层责任人与时间点，超期须触发升级督办。
